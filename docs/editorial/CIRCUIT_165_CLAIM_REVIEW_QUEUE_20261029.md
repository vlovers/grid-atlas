# 165 circuit stories — claim-level review queue

**Status: offline research workflow, not publication approval.** This package builds on the merged [#355 offline bilingual reading desk](https://github.com/vlovers/grid-atlas/pull/355) and the existing [33-dossier source triage](circuit-experience-v3/F1DB_33_EXPANSION_SOURCE_TRIAGE_20261028.json). It does **not** rewrite manuscripts or duplicate the five-circuit review candidate in draft #296.

## Reviewer workflow

From the repository root (Node 24):

```sh
pnpm review:circuits:html > /tmp/grid-atlas-165-review.html
pnpm review:circuits:claims > /tmp/grid-atlas-165-claim-queue.json
pnpm review:circuits:claims:md > /tmp/grid-atlas-165-claim-worksheet.md
pnpm review:circuits:claims:html > /tmp/grid-atlas-165-claim-review.html
node --test tests/circuit-expansion-review-export.test.mjs tests/circuit-claim-review-queue.test.mjs tests/circuit-claim-review-html.test.mjs
```

The original reading packet provides paired EN/UK reading. The separate claim-review HTML desk groups all 165 worksheets into 33 risk-ranked circuit sections with keyboard-accessible jump links, source links, side-by-side EN/UK passages, explicit pending checks, sentence candidates and printable layouts. It is a static offline file: no JavaScript, network fetches, image assets, trackers, approval forms or persistence. Its risk priority is only a heuristic, not a review decision.

The HTML packet provides paired EN/UK reading. The JSON/Markdown queue gives **165 story-specific review worksheets** ranked by explicit evidence-risk heuristics. Each record carries its source links, exact draft fingerprint, complete bilingual copy, sentence candidates, numerical comparison and five pending checks: classification, historical context, bilingual meaning, circuit identity and editorial quality.

A story may contain multiple historical claims in one sentence, and a claim may span several sentences. **Sentence candidates are not atomic claim verification.** The reviewer must separate the claims, inspect sources and locate supporting passages independently. The queue does not fetch sources or invent review decisions.

## Risk rules (deterministic, not a truth score)

| Flag | Weight | Interpretation |
| --- | ---: | --- |
| Five stories share one URL | +5 | Seek corroboration for each independent historical assertion |
| Only classification/results links | +3 | Results do not prove race circumstances, significance or technical context |
| Race-classification URL has no matching story year | +3 | Confirm event/year and the source's intended scope |
| EN/UK numerals differ | +2 | Compare quantities and translation manually; decimal commas normalize |
| Other source type | +1 | Inspect origin, provenance and claim-level relevance |

Scores sort the worklist; they do **not** approve, reject or establish accuracy. Numeric differences are heuristic: spelled-out numbers, dates, rounding and formatting can produce false positives or misses.

## Publication boundary

The queue is generated by reading the already fail-closed #355 packet; it does not write to the application, database, release manifest or media registry. Every record explicitly says `reviewer_decision: not_recorded`, `independently_verified: false` and `publication_allowed: false`. The SHA-256 identifies the exact **draft**, not a human signature.

For a real release, a distinct editor must independently verify the **exact final EN/UK edition** and record the decision through the existing approved release process. Do not copy this queue's SHA-256 into `circuit-release.json`; that manifest digests a different candidate edition and has a separate human gate. No photographs are licensed or published by this package.
