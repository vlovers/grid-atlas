## Execution gates for every working session
1. Re-read repository `main`, open pull requests, roadmap, relevant files and exact-head CI. Resolve blockers on PR #299 first, including reviewer feedback and factual claims. Never merge while any required CI fails, is queued or in progress.
2. Choose one independent deliverable covering **20–30 tracks**, or a complete 78-track quality pass; commit substantive work to one cohesive PR. Avoid micro-PRs or generic copy repeated over dozens of pages.
3. Source research before authoring. For each corner claim store the exact circuit and historical layout/year (if relevant), `name`, `turnNumber` only when proven, `origin` only when proven, `technique`/spectator insight with editorial status, source URL and publisher. Keep source attribution per claim where possible; old race classifications confirm results, **not** etymology or corner geometry.
4. Test all EN/UK routes, undefined fields, keyboard/mobile, source links, and correct alignment with archive circuit IDs. Verify no duplicate IDs and accurate count per evidence tier.
5. When CI is green and branch up to date and conflict-free, merge if authorized, then verify merge SHA. No deployment claims without deployment evidence.
6. Report verified PR/commit, green/pending/failing checks, actual number of verified corners, and remaining editorial gaps. No inflated coverage claims.

## Content order
### Stage 1 — trustworthy circuits (highest priority)
- Start with 20–30 where named corners have reliable information: verified operator/FIA/Formula1.com material, not generic race classification or a guessed map. Prioritize the 53 circuits presently missing independent corner documentation, but cross-check recent PR before any work.
- Explicitly preserve layout distinctions (e.g. Zeltweg vs Spielberg, Caesars Palace vs modern Las Vegas, old vs new Hockenheim, Pedralbes vs Catalunya, Portimão periods).
- Present three reading levels: **Quick** (why this place matters), **Explore** (2–5 notable named sections, origin, what to watch), **Deep Dive** (period-specific geometry, history, race evidence, provenance).
- For historical venues with no reliable corner metadata, record `not_verified` without inventing turns. Fill with high-quality independent race history only if distinct from existing content.

### Stage 2 — circuit visual experience across all 78
- Editorial but original, Box Box-inspired: source-supported hero statistics, large licensed local circuit SVG with layout selection, what-to-watch cards, greatest drivers/constructors computed from pinned F1DB archive.
- No constant tire compounds (event-dependent), fabricated sector/DRS/speed-trap markers, unofficial corner numbers, arbitrary 1–5 numerical scores, or unsupported lap record.
- Flag era and source alongside all quantitative claims. Mark editorial qualitative descriptions as editorial interpretation, not official statistics.

### Stage 3 — biography and constructor completeness
- After circuit foundation ships, resume documented EN/UK driver biographies and constructor identities. Reuse existing reviewed work and avoid unresolved PR duplication.
- Deepen 20–30 source-backed profiles per batch; include chronology, pivotal races, archival links, human-interest explanation and confirmed provenance. Do not fabricate quotations or personal details.

### Stage 4 — actual media pipeline
- Audit existing registry, licenses, photographer credits, modifications allowed, stored file checksum and suitability.
- Integrate photo assets only if license permits reproduction and attribution and provenance is recorded; otherwise improve owned SVG/typography/layout without presenting vectors as photography.

## Acceptance targets (not current factual counts)
- Exactly 78 circuit identities covered by core story, and separately counted independently sourced corner guides.
- At least two substantive source-backed narrative elements for any claimed 'deep' circuit profile; no copy-pasted 78 near-identical explanations.
- Every historically sensitive event handled with care; qualified when source is incomplete.
- All relevant CI green and reviewer sign-off accurately distinguished from AI review.
